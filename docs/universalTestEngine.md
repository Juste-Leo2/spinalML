# Universal Bit-Exact Test Engine (`spinalml test`)

The Universal Bit-Exact Test Engine is spinalML's automated hardware-software co-verification framework. Given any top-level `Accelerator` model definition written in SpinalHDL, the CLI command:

```bash
spinalml test path/to/MyModel.scala
```

automatically scaffolds a complete system-on-chip (SoC) simulation environment under **Verilator**, arranges weights and input data in simulated external DDR memory, drives the accelerator through AXI4 memory-mapped and AXI-Lite control interfaces, and verifies cycle-accurate RTL outputs against a bit-exact software oracle (`assert dev == 0.000`).

---

## 1. Engine Architecture

The test engine comprises five decoupled components working in concert:

```
┌────────────────────────────────────────────────────────┐
│               Model Definition (.scala)                │
│             e.g. Mnistw4a8, ResidualMLP                │
└──────────────────────────┬─────────────────────────────┘
                           │
            CLI Scaffolding Pass (cli.py)
                           │
       ┌───────────────────┴───────────────────┐
       ▼                                       ▼
┌─────────────────────────────┐   ┌─────────────────────────────┐
│    WeightMemoryLayout       │   │       MemoryHarness         │
│  - Type inference per layer │   │  - Float packing (BF16)     │
│  - Raw bit-packing (I4..32) │   │  - Byte packing (I8)        │
│  - AXI beat alignment       │   │  - 64-bit DDR word builder  │
└──────────────┬──────────────┘   └────────────┬────────────────┘
               │                               │
               ▼                               ▼
       ┌───────────────────────────────────────────────┐
       │             Simulated DDR Memory              │
       │    Base addresses: Image (0x10000)            │
       │                    Weights (0x20000)          │
       └───────────────────────┬───────────────────────┘
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
┌─────────────────────────────┐   ┌─────────────────────────────┐
│    Verilator SoC RTL Sim    │   │     ModelReplica Oracle     │
│  - DMAReader / DMAReader2D  │   │  - ReplicaTensor (Int/Float)│
│  - Sequential Datapath      │   │  - HWArithmetic (RN-even)   │
│  - TapBuffers / Skip DAG    │   │  - Cast / Quantization ops  │
└──────────────┬──────────────┘   └────────────┬────────────────┘
               │                               │
               │ Hardware Logits               │ Software Logits
               └───────────────┬───────────────┘
                               ▼
               ┌───────────────────────────────┐
               │    UniversalTestHarness       │
               │  - Dynamic FloatML decoding   │
               │  - Bit-exact assertion        │
               │    dev = max(|hw - sw|) == 0  │
               └───────────────────────────────┘
```

### 1.1 CLI Scaffolding (`cli.py`)
When `spinalml test <model.scala>` is executed:
1. Inspects the file to extract the package name and accelerator class name.
2. If `--legacy` is passed, searches for existing handcrafted test suites in `spinalML/test/src/` (e.g. `Mnistw4a8Test.scala`).
3. Otherwise, generates a self-contained simulation test file in `spinalML/test/src/cli_test_temp/AutoGeneratedCircuitTest.scala`.
4. Detects the pipeline data type (`pipelineDtype`) to determine whether the input tensor is in the integer domain (`SInt`/`UInt`) or floating-point domain (`FloatML`).
5. Generates deterministic input stimuli and orchestrates execution via `mill.bat spinalML.test.testOnly cli_test_temp.AutoGeneratedCircuitTest`.

### 1.2 DDR Memory Layout & Bit-Packing (`WeightMemoryLayout.scala`)
Different neural network layers require different bit-widths for weights and biases (e.g. `I4` weights for quantized convolutions, `FP8_E4M3` for quantized linear layers, `I16` for bias accumulators).

`WeightMemoryLayout` computes offsets mimicking `Sequential.scala`:
- **Dynamic Type Propagation**: Inspects each layer's `layer.weightType(inType)` and `layer.outType(inType)` to allocate correct memory regions.
- **Beat Alignment**: Pads each layer's weight and bias region to 64-bit AXI beats using `MemLayout.alignToBeat(offset, beatBytes)`.
- **Sub-Byte & Multi-Byte Packing (`packRawBits`)**:
  - `4-bit (I4)`: 2 signed nibbles packed per byte: `(low & 0xF) | ((high & 0xF) << 4)`.
  - `8-bit (I8, FP8_E4M3, FP8_E5M2)`: 1 byte per element.
  - `16-bit (I16, BF16)`: 2 bytes little-endian.
  - `32-bit (I32, FP32)`: 4 bytes little-endian.

### 1.3 Memory Harness (`HarnessUtils.scala`)
Handles image tensor placement in DDR memory:
- `MemoryHarness.packFloats(floats)`: Packs 16-bit BF16 floats (4 per 64-bit word).
- `MemoryHarness.packBytes(bytes)`: Packs 8-bit integer bytes (8 per 64-bit word) with zero-padding to AXI beats for `I8` image inputs.

### 1.4 Hardware Execution & Dynamic Decoding (`UniversalTestHarness.scala`)
- Mounts simulated DDR memory pages via SpinalHDL Sim AXI4 master transactors.
- Pulses CSR `start` register (`0x00`) via AXI-Lite and waits for `done` status (`0x04`).
- Captures output stream tokens and decodes them dynamically:
  - `decodeFloat(p: Data)` extracts exact exponent width (`eW`) and mantissa width (`mW`) from the runtime `FloatML` bundle (e.g. `eW=4, mW=3` for `FP8_E4M3`, `eW=8, mW=7` for `BF16`).
  - Supports `UInt` and `SInt` output channels.

### 1.5 Software Oracle & Trace Preview (`ModelReplica.scala` & `LayerReplicas.scala`)
- Implements `ReplicaTensor` dual-representation:
  - `IntTensor(shape, data: Seq[Long], bitWidth: Int)`: Exact 64-bit integer tracking for integer operations.
  - `FloatTensor(shape, data: Seq[F], expBits: Int, mantBits: Int)`: Finite-field floating-point arithmetic obeying hardware RN-even rounding, flush-to-zero, and saturation via `HWArithmetic`.
- Prints formatted layer-by-layer previews (first 3, last 3, min, max) for instant visual debugging:
```text
Layer  0 [Conv2D    ] : shape 24x24x2      | first3=[40.000, 46.000, 56.000] ... | min=40.000, max=61.000
Layer  1 [ReLU      ] : shape 24x24x2      | first3=[40.000, 46.000, 56.000] ... | min=40.000, max=61.000
Layer  2 [MaxPool2D ] : shape 12x12x2      | first3=[56.000, 61.000, 56.000] ... | min=56.000, max=61.000
Layer  3 [Cast      ] : shape 12x12x2      | first3=[ 5.000,  5.000,  5.000] ... | min= 5.000, max= 5.000
Layer  4 [Flatten   ] : shape 1x288        | first3=[ 5.000,  5.000,  5.000] ... | min= 5.000, max= 5.000
Layer  5 [Linear    ] : shape 1x10         | first3=[128.000, 128.000, 128.000]...| min=128.000, max=128.000
```

## 2. Supported Layer & Quantization Matrix

| Layer | Pure Floating-Point (`FloatML`) | Pure Integer (`SInt`) | Quantized / Mixed (`wXaY`) | Status in Universal Test |
| :--- | :---: | :---: | :---: | :--- |
| `Conv2D` | ✅ (`BF16`, `FP8`) | ✅ (`I4`, `I8`, `I16`) | ✅ (Hybrid W4A8) | **Supported** (Multi-channel `inChannels > 1` in int domain requires features-last layout). |
| `Conv1D` | ✅ (`BF16`, `FP8`) | ❌ | ❌ | **Supported** in FloatML. |
| `Linear` | ✅ (`BF16`, `FP8`) | ❌ | ✅ (`wXaY` via Cast) | **Supported** in FloatML & wXaY; pure integer Linear pending replica extension. |
| `ReLU` | ✅ | ✅ | ✅ | **Supported** (Bit-exact clipping). |
| `LeakyReLU` | ✅ | ❌ | ❌ | **Supported** in FloatML. |
| `MaxPool2D` | ✅ | ✅ | ✅ | **Supported** (Line buffers + delay lines bit-exact). |
| `MaxPool1D` | ✅ | ❌ | ❌ | **Supported** in FloatML. |
| `AvgPool2D` / `AvgPool1D` | ❌ | ❌ | ❌ | *Hardware RTL ready; pending replica interpreter wiring.* |
| `Cast` | ✅ (Float -> Float) | ✅ (Int -> Int) | ✅ (Int -> Float + scale) | **Supported** (Bridge between integer and float domains). |
| `Flatten` | ✅ | ✅ | ✅ | **Supported** (Features-last). |
| `BatchNorm1D` | ✅ | ❌ | ❌ | **Supported** in FloatML. |
| `Add` (DAG) | ✅ | ✅ | ✅ | **Supported** (Skip connections). |
| `Concat` (DAG) | ✅ | ✅ | ✅ | **Supported** (Multi-branch merge). |
| `Sigmoid` / `Tanh` | ❌ | ❌ | ❌ | *Hardware RTL ready; pending replica interpreter wiring.* |
| `Softmax` | ⚠️ | ⚠️ | ⚠️ | *Hardware computes full LUT exp/sum; replica passes logits.* |
| `ClassicalAttention` | ❌ | ❌ | ❌ | *Hardware RTL ready; pending replica interpreter wiring.* |

### Supported Data Types
- **Integers**: `I4` (4-bit signed), `I8` (8-bit signed), `I16` (16-bit signed), `I32` (32-bit signed).
- **Floating-Point**: `BF16` (`FloatML(8, 7)`), `FP8_E4M3` (`FloatML(4, 3)`), `FP8_E5M2` (`FloatML(5, 2)`).

## 3. Rules for Authoring Testable Models

To ensure a new model passes verification under `spinalml test`:

### Rule 1: Place files inside `spinalML/src/`
Mill only compiles sources inside `spinalML/src/` and `spinalML/test/src/`. New models should be placed in `spinalML/src/spinalML/examples/` (or any package under `spinalML/src/`).

### Rule 2: Provide default constructor arguments
The test generator instantiates models using `new ModelName()`. Ensure `axiConfig` has a default value:
```scala
// Correct:
case class MyModel(
  override val axiConfig: Axi4Config = Axi4Config(addressWidth = 32, dataWidth = 64, idWidth = 4)
) extends Accelerator(...)

// Incorrect (will fail compilation during test scaffolding):
case class MyModel(override val axiConfig: Axi4Config) extends Accelerator(...)
```

### Rule 3: Use supported layers
Compose models using validated layers (`Conv2D`, `Linear`, `ReLU`, `MaxPool2D`, `Cast`, `Flatten`, `Add`, `Concat`, `BatchNorm1D`).

### Rule 4: Match input data type
- For image models with integer activations, set `dataType = I8()`.
- For floating-point models, set `dataType = BF16()` or `FP8_E4M3()`.

## 4. Current Limitations & Roadmap

1. **Pure Integer Dense Layer (`Linear`)**:
   Currently, `Linear` expects a `FloatTensor` input. Pure integer MLP networks (without `Cast` to float) will be supported by implementing an integer accumulator path in `ModelReplica`.
2. **Extended Layer Coverage in `ModelReplica`**:
   - `AvgPool2D` and `AvgPool1D`.
   - `Sigmoid` and `Tanh` non-linearities.
   - Attention blocks (`ClassicalAttention`, `MultiHeadAttention`).
3. **Softmax Output Verification**:
   `ModelReplica` currently treats `Softmax` as a pass-through to verify pre-softmax logits. An exact software LUT model matching `Softmax1D.scala` will enable bit-exact probability verification.
4. **Input Packing for `I16` and `I32` Image Tensors**:
   `MemoryHarness.packBytes` currently packs 8-bit bytes. Adding 16-bit and 32-bit word packers will enable models with `dataType = I16()`.
5. **CLI Test Source Mirroring**:
   If a user specifies a file outside `spinalML/src/` (e.g. project root), `cli.py` will automatically mirror it into a temporary build directory before triggering Mill.
