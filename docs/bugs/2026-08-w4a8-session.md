# MNIST W4A8 Bring-Up Session — August 2026

Summary of the mixed-precision follow-up to the BF16 MNIST flow: a true
**INT4 convolution** (nibble-packed weights, integer activations, integer
accumulator) followed by a **Cast to FP8 E4M3** for the final Linear layer,
validated end-to-end black-box under Verilator — final result **5/5 digits
correctly classified**, logits within E4M3 rounding of the software replica.

Two real framework defects were uncovered and fixed (_PATCHED_) — one of them
a silent memory-region aliasing, the other a data-corrupting row-fetch bug
that had been latent since the 2D reader was written — plus one robustness
edge and several additive features. No golden model was used for validation:
the trained network itself is the reference.

---

## What was built

* [`spinalML/src/spinalML/examples/Mnistw4a8.scala`](../../spinalML/src/spinalML/examples/Mnistw4a8.scala)
  — same trained topology as `Mnist`, but with an explicit integer/float
  boundary:

```
Image I8 {0,1} -> Conv2D(W:I4 nibbles, A:I8, acc:I16, bias quantized)
              -> ReLU (int) -> MaxPool2D (int)
              -> Cast(FP8_E4M3, scales = Seq(175/2048))   // dequant boundary
              -> Flatten -> Linear(FP8 x FP8) -> 10 logits
```

* [`spinalML/test/src/spinalML/examples/Mnistw4a8Test.scala`](../../spinalML/test/src/spinalML/examples/Mnistw4a8Test.scala)
  — black-box SoC bench: DDR packed with nibble-paired INT4 kernels
  (16 elements per 64-bit beat), I16 quantized biases, E4M3-encoded FC
  weights/biases, raw `{0,1}` pixel bytes; argmax checked against labels.
* Data files: `Mnist/weights_w4a8.txt` (`T_CONV1_WEIGHT_INT4`,
  `T_CONV1_SCALE`, `T_CONV1_BIAS`, `T_FC1_WEIGHT_FP8`, `T_FC1_BIAS`),
  generated by fake-quantizing the BF16 network in PyTorch and evaluating
  in float — so the hardware contract is exactly `Σ(q·s)·x + b`.

### Quantization semantics that made it work

The conv runs entirely in the integer domain: weights are raw int4 codes
(sign-extended on-chip), the accumulator is I16, and the per-tensor scale is
applied ONCE by the post-pooling Cast layer. Bias is folded into the int
domain as `b_q = round(b / s)` (error ≤ s/2 ≈ 0.043). Because the network was
trained on *normalized* pixels (background −0.4242, ink +2.8215) while the
provided samples are binarized, the affine gap was verified harmless: the
software replica scores 5/5 on plain `{0,1}` inputs for every dtype variant
tested (BF16 weights, int4-dequantized weights, full W4A8).

## Framework additions (no behavior change by default)

* **`Cast` spec gains `scales: Seq[Double]`** (`LayerSpec.scala`), forwarded
  by `Sequential` to `ops.cast`. This completes the integer→float boundary
  for pipelines like W4A8 without touching any existing call site.
* **`CastOp` supports SInt→SInt**: pure sign-extending resize between integer
  widths (used to widen fetched I4 weights to the I8 activation width).
  Previously only SInt→FloatML existed; a narrow-weight Tensor connected to a
  wider matmul port failed elaboration with WIDTH MISMATCH.
* **`Sequential` widens narrow SInt conv weights automatically**: when a
  Conv2D's weight dtype is a narrower SInt than its activation dtype, a cast
  stage is inserted after the weight double-buffer (mirroring the existing
  Linear wXaY special-case).
* **Weightless models no longer break the arbiter**: `dmaAxiConfig` kept the
  full id width when the model has a single DMA.

## Bug 1 — Sub-byte weight regions silently aliased the next region — _PATCHED_

`Sequential` advanced its DDR offset with `elements * (bitsWidth / 8)`.
For I4 weights the division floors to **zero bytes**, so the conv bias region
was allocated at the *same address as the kernels*: the "bias" values read by
the hardware were the first weight bytes reinterpreted as I16 (observed as a
constant `+4369 = 0x1111` baseline added to every output, independent of the
image). BF16 flows never noticed because 16 bits divide evenly.

### Fix

Region size is now computed with the ceil applied to the **whole region**
(`Sequential.scala`):

```scala
currentMemoryOffset = alignToBeat(currentMemoryOffset + (elements * bitsWidth + 7) / 8)
```

so 50 nibbles occupy 25 bytes → 32 aligned, matching the packing convention
benches must use (pad each section independently to a 64-bit word). Applied
to both weight and bias offsets.

Fingerprint for future hunts: outputs equal to bias-only values plus a
constant garbage baseline that survives input changes.

## Bug 2 — DMAReader2D corrupted every non-word-aligned row — _PATCHED_

With I8 pixels, a 28-pixel row spans 3.5 AXI beats. The 2D reader issued
whole-beat row fetches from the raw row address and never trimmed the tail,
so each row's stream carried 32 elements: 28 valid + the first 4 bytes of the
next row — shifting every downstream window. Worse, row start addresses
alternate between 8-byte-aligned and +4 (`28·r mod 8`), and unaligned starts
made the returned words land shifted inside their beats, injecting zeros and
duplicating strokes across rows. BF16 flows were immune only because 56-byte
strides are always word-aligned — the bug was latent since the 2D reader was
written.

Symptoms during bring-up: pooled feature maps with ~50× inflated sums,
logits pinned at large negative E4M3 saturation codes, deterministic across
runs (this was *not* the known one-shot restart issue).

### Fix (`DMAReader2D.scala`, rewritten)

* Rows are strictly serialized at the 2D level: the next row command is
  issued only after every output beat of the current row crossed the trim
  stage, making row boundaries exact regardless of internal pipelining.
* Unaligned row starts are handled properly: the fetch address is rounded
  DOWN to the beat boundary, enough words are fetched to cover
  `[headSkip, headSkip + W)`, and a trim stage masks leading/trailing extra
  elements. The element stream then carries exactly `shape(1)` elements per
  row; with aligned, exact-width rows it is a transparent passthrough
  (BF16/I16 flows unchanged).

Verified standalone: 784/784 elements bit-exact on the real image through
the trimmed path (896 raw fires, 112 suppressed).

Fingerprint: content-dependent corruption starting at fixed window indices,
values far outside any single-window bound, alternating clean/corrupted rows
matching address alignment parity.

## Edge found along the way — weightless models vs arbiter id width — _PATCHED_

A model with zero weighted layers has a single DMA, but `dmaAxiConfig`
still shrank `idWidth` while the single-master path bypasses the arbiter,
failing elaboration with WIDTH MISMATCH on `ar.id`. Single-DMA models now
keep the full config.

## Debug war stories worth remembering

* **Trust the replica, then audit the replica**: the first Python golden
  scored 0/5 *because it consumed the FC weights in file order*, forgetting
  the features-last column remap that the hardware convention requires. Once
  corrected, every dtype variant scored 5/5 — which flipped the investigation
  from "the quantized net is broken" to "the hardware deviates".
* **Mini-model bisection pays**: three tiny Accelerators truncating the chain
  (`conv` / `+ReLU+Cast` / `+Linear`) isolated the healthy stages in minutes;
  the remaining divergence had to live in what they shared.
* **Control-group probes exonerate**: rerunning a variant with word-aligned
  rows (I16 pixels) proved the trim wasn't the corrupting agent before any
  framework code was rewritten a second time.
* **Impossible magnitudes are information**: outputs of ±1732 with ±1 kernels
  over binary pixels cannot come from one window — that observation alone
  ruled out entire bug classes and eventually led to counting the global
  fire/suppress totals (896/112, exactly right) which moved suspicion from
  logic to bench encoding.
* **The 56 reveal**: an all-ones image produced `25×56 − bias` outputs —
  `0x38 = 56 = FP8(1.0)`. The bench had been packing *float-encoded* pixels
  into an *integer* activation pipeline. Every "impossible" number above was
  this constant in disguise; the actual RTL needed only Bug 1 + Bug 2 fixes.
* Bench-side lesson: hold `cmd.valid` until `cmd.fire`, not `cmd.ready` —
  waiting on ready alone can cover the whole transfer once components assert
  readiness only at completion, leaving the collector nothing to observe.

## Known limitation confirmed — one-shot restarts

Unchanged from the BF16 session: each inference runs in its own fresh
simulation state (see roadmap *Inter-start state re-arming*). The earlier
suspicions of flaky streaming were disproven — failures reproduced
bit-identically across repeated runs.

## Improvement leads (upscaling)

1. **Fold the affine input transform properly**: if normalized inputs ever
   become necessary (not just robust {0,1}), fold `x_bg` into the quantized
   bias via the kernel-sum identity `y = sγ·Σqd + [b + s·x_bg·KSUM_c]` — the
   algebra is proven, only the packer needs the extra term.
2. **Per-channel conv scales**: `CastOp` already supports per-beat scales and
   conv weight beats map 1:1 to output channels; exposing per-channel conv
   dequantization would raise accuracy on deeper nets for free.
3. **Wider accumulators for float paths**: the FP8 Linear still accumulates
   in FP8; routing matmul's `accType` to BF16 internally would mirror the
   int path's headroom.
4. **Formal coverage for the new 2D FSM** — DONE in the follow-up session:
   the serialized drain-wait and trim counters are now proven with CVC4
   (addressing, keep-window geometry, per-command beat accounting, covers;
   lanes=1 free-stride contract plus lanes>1 under the documented alignment
   precondition). See `symbolicTest/memory/DMAReader2DFormal.scala`.
5. **Sub-byte activation dtypes** remain unsupported end-to-end (byte-addressed
   DMA); the widen-cast pattern proven here for weights could be mirrored if
   A4 flows ever matter.
